# hubx-gw

Owner agent: `backend-go`. Read the root `AGENTS.md` first; the constitution prevails.

1. **Purpose.** Single entry point of the system. Reverse proxy to hubx-api; no domain logic.
2. **Layout.** `cmd/gw/main.go` (loads config, starts the server). `internal/config` (own stdlib reader), `internal/server` (builds the handler chain; testable), `internal/proxy` (`httputil` reverse proxy, `StripPrefix /api`, removes the API's security and `Access-Control-*` headers), `internal/middleware` (`SecurityHeaders`, `CORS`, `JWTValidation`, `RateLimit`), `internal/ratelimit` (in-memory sliding-window limiter, injected clock). Chain order: `SecurityHeaders -> CORS -> JWTValidation -> RateLimit -> mux`.
3. **Conventions.** Go stdlib + approved `golang-jwt/jwt/v5` for JWT validation only (never issuance) and `go.uber.org/mock` for tests. Same test layout as hubx-api: every package with tests has `test/` and generated `mocks/` (`go -C hubx-gw generate ./...`; `internal/ratelimit/mocks` holds the `Limiter` mock). `log/slog` JSON. `ReadHeaderTimeout: 5s`. Own `GET /health`; `GET /api/health` is proxied to the API.
4. **Config.** `application.properties` in this folder, read by `internal/config` (precedence: env var > `application-<profile>.properties` (`APP_PROFILE`) > `application.properties` > code default; every key has a default, so env vars apply even without the file). Keys: `server.port` (8080, alias `PORT`), `api.url` (http://localhost:8081, env `API_URL`), `cors.allowed-origins` (default EMPTY in code and file: no cross origin is allowed; comma separated `scheme://host[:port]`, http/https only, no path/query/userinfo; `*` and `null` are rejected; an empty value grants nothing; set it via `CORS_ALLOWED_ORIGINS` only where a browser calls the gateway cross-origin; local Vite works without it because it proxies `/api` same-origin, so the gateway processes the request regardless of the `Origin` header it forwards), `ratelimit.requests-per-minute` (120, per validated `sub`), `ratelimit.sign-in-requests-per-minute` (10, per normalised email). Limits are strict positive integers. An empty environment value counts as unset. Secrets `jwt.secret` and `gateway.secret` come only from the environment (`JWT_SECRET`, `GATEWAY_SECRET`): a value in a file is ignored. Invalid values or missing secrets stop the start with an error that names keys and never prints values. Run from this folder (`config.Load(".")`).
5. **Commands.** `go -C hubx-gw test ./...`, `go -C hubx-gw build ./...`, `gosec ./...`, `govulncheck -C hubx-gw ./...`.
6. **Contract.** `contracts/gateway-perimeter.md`. Validates JWT on all routes except `/health`, `/api/health` and `/api/auth/sign-in`; every response (including 401, 404, 413, 429, 502) carries the security headers exactly once; CORS answers preflights itself (no JWT, no limit, never forwarded) and grants only configured origins, never credentials; rate limits answer `429` with `Retry-After`; injects the shared secret toward the API; forwards `Authorization` untouched (API validates independently, Constitution II).
7. **Rate limiting.** Users are limited by the `sub` of an already validated JWT (read from the request context, never from headers or network address). Sign-in is limited by SHA-256 of the email normalised like the API (trim + lowercase), decoded with the same `json.NewDecoder` struct shape as the API; only exact `POST /api/auth/sign-in`; at most 8192 bytes are read (over: `413`) and the body is restored byte for byte. Health and preflights are never limited. Two independent limiters, 10000 identities each, least recently seen evicted. **Limitation:** state is in memory per gateway instance: it resets on restart and each instance counts separately.
8. **Never.** Business rules, JWT issuance, database access, imports from hubx-api, logging emails or secrets.
